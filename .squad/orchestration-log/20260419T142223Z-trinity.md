## Task

Fix rows rendering above the sticky `<thead>` when scrolling the Movimientos table. User (Pedro) reported transactions "pass behind the header to the top of the screen."

## Root Cause

`.ot-shell__main` had `padding-top: var(--space-9)`. That padding band is part of the scrollport, and `sticky top: 0` anchors to scrollport top—so upward-scrolling rows paint through the padding band above the pinned thead.

## Solution

1. `.ot-shell__main` → `padding: 0 var(--space-10) var(--space-9)` (top gutter removed).
2. Top gutter moved to `.ot-page-header` → `padding-top: var(--space-9)`.
3. All three screens (Panel, Movimientos, Saldo) already lead with `.ot-page-header`, so visual spacing unchanged.
