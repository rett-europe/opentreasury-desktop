Fixed 7 backend findings from Copilot PR #4 round 2 on commit `57ae73b`. Tightened update-event invariants at both schema and handler boundaries to prevent no-op mutations and empty-string pollution.

## Canonical invariants established

1. **All update schemas now validate that at least one field carries a real change.** Refines check `Object.values(changes).some(v => v !== undefined)` instead of just checking key count.

2. **Empty strings are never persisted for optional string fields.** Handlers trim + delete empty values (matching create-time semantics). Fields affected: `bankName`, `label`, `iban`, `color` (accounts); `color` (tags, categories, subcategories).

3. **Handlers re-check for non-empty changes AFTER normalisation.** Whitespace-only strings collapse during trim, leaving `{}`, which short-circuits with `SCHEMA_INVALID` before appending an `Updated` event.

4. **Schema and handler rejections aligned.** `createSubcategoryRequestSchema.name` now enforces `.min(1)`, matching handler's whitespace-rejection logic.
